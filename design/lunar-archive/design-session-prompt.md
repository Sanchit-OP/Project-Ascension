# Prompt for the Lunar Archive design session

Paste everything below the line into a new Claude Code session opened on `E:\code\Project-Ascension`.

---

You are the **design session** for the Lunar Archive in Project-Ascension, a Minecraft 1.21.1
NeoForge mod project. Another session (the "logic session") is working in the main checkout at the
same time, so **work in your own git worktree**:

```
git worktree add -b lunar-archive-design ../Project-Ascension-archive main
```

and do all your work there. Commit as you go. Do not push.

**Read first, in this order:**
1. `docs/technical/lunar-archive-format.md`: your contract with the logic session. It says exactly
   what you own and what you must not touch, the block and item ids, the eight inscription ids and
   where each should sit, the template rules, and the handover checklist. If you need something
   it cannot express, propose a change to that document rather than working around it.
2. `docs/technical/art-guide.md`: how art is made here. The hard rules: **original art only**
   (never copy, trace or sample vanilla, another mod or a pack), **art is code** (every PNG and
   every `.nbt` comes from a seeded script in `tools/`, and re-running it reproduces the committed
   files byte-for-byte), light from the top-left, **teal is the network's colour**, the **diamond
   eye** is its motif, no accidental symbols.
3. `docs/lore/world.md` and `docs/lore/civilization.md`: the story the building tells. A
   civilisation that spanned every nearby planet through the gateways, then something ended it.
   The Archive is where the player first learns that. Tone: awe and loss, abandoned in a hurry,
   not horror.
4. `docs/technical/gateway-portal-design.md` and `moon-materials-art.md`: the visual language
   already on the Moon (lunar basalt, anorthosite, inscribed gatestone, the rune ring). The
   Archive is the same builders' work, so it should look like it.

**What to build:** the Archive itself, a vault cut into the Moon with a surface marker you can
see from far away, as vanilla structure templates generated by `tools/generate-lunar-archive.py`.
Rooms, in the order the player meets them: the way down, a hall of murals (block art that shows,
without words, the builders crossing between worlds), plinths holding the eight inscriptions, the
orrery chamber (the heart: logic draws a hologram of the solar system above the
`archive_orrery` block), the innermost sealed room, and a small stores room. Plus the look of the
three blocks/items logic gives behaviour to (`archive_plinth`, `archive_orrery`,
`archive_tablet`), and any decorative blocks you need (mural panels, friezes, rune strips),
registered the way `GatewayDecorBlocks` does it.

**How to work:**
- Write the NBT deterministically (sorted palette, fixed block order, gzip with a fixed mtime) so
  regenerating is a clean `git status`. DataVersion 3955.
- Make previews and **look at them yourself** before calling anything done: an isometric cut-away
  per floor, a floor plan, the surface marker from a distance. Extend
  `tools/render-structure-preview.py` to read `.nbt` if that's the fastest route. Expect several
  rounds of critique.
- Light the vault enough that it doesn't become a monster spawner (the Moon spawns hostiles at
  block light 0).
- Don't touch logic's files: Java behaviour, `WorldsContent`, worldgen JSON, loot tables, the
  lore text in `en_us.json` for `archive.*` keys. Your lang names for blocks and items are fine.
- `./gradlew :modules:worlds:build` must pass before each commit.

**Hand back** when the contract's checklist is done: a design note
`docs/technical/lunar-archive-design.md` ending in a live checklist, previews in
`design/lunar-archive/`, the `surface_y` number and the list of piece names for the logic session,
and the branch rebased onto `main` so it fast-forwards. Then tell Sanchit it is ready to merge.
